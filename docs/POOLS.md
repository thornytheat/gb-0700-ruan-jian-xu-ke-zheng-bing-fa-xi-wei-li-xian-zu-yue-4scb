# 共享池与旧租约契约

产品线合并后，CAD 与 Render 共用一个席位池，但既有租约仍按签发时的产品
契约核验与释放。

## 三个身份

| 名称 | 含义 | 是否随合并改变 |
|---|---|---|
| 原产品契约 `contract` | 租约/采购/回执签发时登记的产品编号（CAD、RENDER，或合并名） | 不改变 |
| 席位池 `pool` | 当前统一限席的单位；CAD 与 RENDER 都归入 `CAD+RENDER` | 由契约推导，不落库 |
| 合并产品 | 新租约的签发名称 `CAD+RENDER` | 新租约直接以池名签发 |

- 旧租约的 `contract` 永远保留原产品，即使池已合并。全量重映射会破坏旧回执。
- 释放只匹配 `(contract, lease_id, version)`；指向合并产品或另一契约的同号回执
  不会结束旧租约，而是记为 `RELEASE_CONTRACT_MISMATCH`；同契约但版本不符记为
  `RELEASE_VERSION_MISMATCH`。两者都进入补传审计与证据 `release-check` 行。
- 新租约用合并产品名录入（`CAD+RENDER`，别名见 `app/pools.py`），契约即池名。
- 池内限席把各原契约租约的席位相加后与「各原契约采购量之和」比较，不重复
  计算任何一条采购记录。旧版分产品视图则只按各自契约的采购量分别限席。

## 池切换状态机

`GET /api/pools/{pool}` 查看状态，`POST /api/pools/{pool}/switch` 执行或接续。

| 状态 | 视图 | 含义 |
|---|---|---|
| NONE | 合并池 | 没有切换记录；按合并池统一限席 |
| PENDING / INTERRUPTED | 旧版分产品 | 切换未完成；页面与证据保留分产品视图 |
| COMPLETED | 合并池 | 全部旧租约已登记迁移 |

- 切换只登记迁移台账（`pool_migrations`），从不回写租约或采购输入。
- 重试同一合并按 `lease_key` 去重，只接续未迁移租约；已迁移项不会重复占席。
- 切换身份就是旧租约集合：提交的集合必须与已登记的一致才允许接续。缺少、
  增加或改写任一旧租约（例如切换期间补传旧回执）返回 409 `SWITCH_CONFLICT`，
  须先 `POST /api/pools/{pool}/reset` 再重新开始。以合并产品签发的新租约不属于
  旧租约集合，不改变合并身份，也无需迁移。
- `interrupt_after=N` 仅用于演练中断：只登记前 N 条未迁移租约，状态记为
  INTERRUPTED，视图保持旧版分产品。再次提交同一请求即接续剩余部分。
- 切换未完成时以合并产品签发的新租约无法在旧版分产品视图里单独限席：采购条带
  单列「待切换」行显示其份数与席位，不并入任何原产品；切换完成后并入共享池。

## 页面与证据

- 页面 KPI 显示有效租约、并发峰值、超用区间、忽略心跳、隔离事件与席位池数；
  并发面板标注当前视图（共享池 / 分产品）；采购条带显示池容量与逐契约超用归属，
  席位池面板显示原契约、迁移进度、尝试次数与迁移台账。
- 证据 CSV 同时包含：`lease`（原产品凭据 + 所在池）、`pool-switch`、
  `pool-migration`、`pool-segment`（并发 / 容量 / 超用 / 逐契约容量 / 责任）、
  `pool-attribution` 汇总行、`release-check`（契约或版本不匹配的释放回执），
  以及原有 `quarantine`、`result` 行。
- 池状态变化会产生新的证据快照（摘要里含池令牌与快照类型），历史快照保持原
  计算结果，不会被后续切换改写。
